# 계획서: 가맹점 응대 기록 쌓기 (구글시트 연동)

- 작성일: 2026-11-23
- 상태: **승인됨 (11/23) · 구현 완료**
- 관련: `merchant-reply/index.html`, `docs/plans/2026-11-23-merchant-reply-tool.md`

## 1. 목표

스카이티제이 팀장으로서 가맹점 응대를 **한 건도 빠짐없이 한 줄씩 기록**하고, 쌓인 데이터로
유형별 건수·해지 사유·A/S 증상·처리 기간 같은 통계를 본다.

- 기록 입력은 이미 쓰는 **가맹점 답장 도구**에서 한다 (따로 두 번 쓰지 않기).
- 지금은 응대 기록이 **카톡 업무방에만** 흩어져 있다. 검색·집계가 안 되는 게 문제.
- 기록 저장소는 **새 구글시트**를 만든다 (지팀 본인 구글 계정, 비공개). 기존 시트 없음 → Apps Script `setup` 한 번으로 탭·열·통계까지 자동 생성.
- **카톡 업무방 흐름은 그대로 둔다.** 업무방에 올릴 메모를 복사하는 그 순간에 시트에도 같이 쌓이게 해서, 일하는 방식은 안 바뀌고 기록만 남게 한다.
- 통계는 **시트 안의 "통계" 탭**에서 본다. 공개 GitHub Pages 에는 데이터가 절대 올라가지 않는다.

하지 않는 것: 가맹점 DB(CRM) 전체 구축, 카톡 자동 수집, 업무엑셀·수금방 대체. (나중 단계 후보)

## 2. 시트 구조

스프레드시트 1개, 탭 3개.

### 탭 ① `응대기록` — 1건 = 1줄

| 열 | 이름 | 채우는 곳 | 비고 |
|---|---|---|---|
| A | 접수번호 | 자동 | `261123-1430-K7` (날짜-시각-임의 2자). 도구가 만들어 메모 첫 줄에도 넣음 → 오프라인·한 줄 복사에서도 같은 번호 |
| B | 접수일시 | 자동 | |
| C | 유형 | 도구 | A/S·교체·해지·수수료·신규·승계 |
| D | 상호 | 도구 | |
| E | 주소 | 도구 | |
| F | 연락 온 번호 | 도구 | |
| G | 발신자 | 도구 | 대표/직원/가족 + 이름 |
| H | 장비 모델 | 도구 | |
| I | 요지 | 도구 | 유형별 핵심 1개: A/S·교체=증상, 해지=철수사유, 수수료=문의 요지, 신규=연락 경로, 승계=관계 |
| J | 세부 | 도구 | 유형별 보조값: 처리내용 / 교체방식 / 사유상세 / 카드사 / 사업자유형 / 포스교육 |
| K | 방문예정 | 도구 | 있으면 |
| L | 가맹점 과실·비용청구 | 도구 | O/X |
| M | 위약금(원) | 도구 | 해지만, 숫자 |
| N | 승계 가능 | 도구 | 해지(폐업)만 |
| O | 수금방 기록 | 도구 | O/X |
| P | 상태 | 도구=접수, 이후 시트에서 수정 | 접수 → 진행 → 완료 / 보류 |
| Q | 완료일 | 시트에서 입력 | 처리 기간 계산용 |
| R | 담당 | 도구(기기 설정값) | 나중에 직원도 쓰면 구분 |
| S | 메모 전문 | 도구 | 업무방 접수 메모 그대로 (마스킹 후) |
| T | 비고 | 시트에서 입력 | |

- 상태·완료일·비고는 처리 후 시트에서 직접 고친다 (드롭다운 + 조건부 서식).
- 열이 고정이라 나중에 유형별 칸이 늘어도 I/J/S 에 담겨 통계가 깨지지 않는다.

### 탭 ② `통계` — 수식으로 자동 집계
- 이번 달 / 지난 달 유형별 건수, 월별 추이
- 해지 사유 순위, 해지 건 위약금 합계, 승계 전환 건수
- A/S·교체 증상 순위, 장비 모델별 고장 건수
- 미완료(접수·진행) 건 목록, 평균 처리 일수
- 같은 상호 반복 문의 (최근 90일 2회 이상)

### 탭 ③ `설정` — 유형·상태 드롭다운 목록, 담당자 목록

## 3. 연동 방식 (결정 필요)

지금 답장 도구는 **"외부 통신 0"** 원칙(가맹점 정보가 기기 밖으로 안 나감)으로 만들어졌다.
시트에 자동으로 넣으려면 이 원칙을 일부 바꿔야 해서, 두 가지 안을 둔다.

### 안 A (추천): 버튼 하나로 시트에 바로 저장
1. 시트에 Apps Script 를 붙이고 **웹 앱**으로 배포 (지팀 계정으로 실행).
2. 답장 도구 "회사 정보 설정"에 **웹 앱 주소 + 비밀키**를 넣는다 → 그 기기 localStorage 에만 저장, 저장소·공개 페이지엔 없음.
3. 결과 화면의 업무방 메모 버튼을 **「복사 + 시트 기록」** 하나로 바꾼다 → 카톡에 붙여넣을 메모가 복사되면서 동시에 위 열 구성대로 1줄 전송 → "기록됨 (20261123-001)" 표시. 메모 맨 위에 접수번호가 붙어, 카톡 업무방과 시트를 번호로 맞춰 볼 수 있다.
4. Apps Script 는 비밀키가 맞을 때만 받고, 아니면 거절.

- 장점: 진짜 버튼 하나. 빠짐없이 쌓인다.
- 바뀌는 점: 설정한 기기에서만, 버튼을 누를 때만 구글(script.google.com)로 통신한다. 설정 안 한 기기는 지금처럼 통신 0.

### 안 B: 통신 없이 "시트용 한 줄 복사"
- 버튼을 누르면 탭으로 구분된 한 줄이 복사되고, 시트 맨 아래 칸에 붙여넣는다.
- 장점: 외부 통신 0 유지. 단점: 매번 시트를 열어 붙여넣어야 해서 빠지기 쉽다.

→ **A 를 기본으로 하되, 설정 안 된 기기에서는 B(한 줄 복사)가 자동으로 대신 나오게** 한다.

## 4. 개인정보 처리

- 시트는 지팀 구글 계정 소유, 공유는 본인(필요 시 직원)만. 링크 공개 금지.
- 웹 앱 주소·비밀키·시트 주소는 **저장소 파일, 커밋, 공개 페이지 어디에도 넣지 않는다.** 기기 설정에만.
- 보내기 전 지금처럼 **주민번호·사업자번호 마스킹** 적용. 위약금 계산용 계약일·임대료 등 계산 원값은 보내지 않고 결과 금액만.
- 도구 화면의 가맹점 입력값은 지금처럼 기기에 저장하지 않는다 (기록은 시트에만).
- 보관 기간은 지팀이 정한다 (예: 해지 완료 후 5년). 필요하면 오래된 줄을 `보관` 탭으로 옮기는 스크립트 추가.

## 5. 바꿀 파일

| 파일 | 변경 |
|---|---|
| `merchant-reply/index.html` | 설정에 웹 앱 주소·비밀키·담당자, 결과 화면에 「시트에 기록」/「시트용 한 줄 복사」, 유형별 → 열 매핑 함수 |
| `merchant-reply/apps-script.gs` (새 파일) | 시트에 붙여넣을 스크립트: 시트·탭·드롭다운·통계 수식 자동 생성(`setup`), 기록 받기(`doPost`) — 주소·키 없음 |
| `docs/plans/…-merchant-log-sheet.md` | 이 계획서 |
| `CLAUDE.md` | merchant-reply 설명의 "외부 통신 0" 문구를 "설정 시 본인 시트로만 전송"으로 갱신 |

설치 순서(지팀이 한 번만): 새 시트 → 확장 프로그램 › Apps Script 에 붙여넣기 → `setup` 실행 → 웹 앱 배포 → 주소를 도구 설정에 입력. 단계별 안내는 구현 때 따로 정리.

## 6. 리스크

- **중복 기록**: 같은 접수번호로 다시 보내면 새 줄이 아니라 그 줄을 수정(상태·완료일·비고는 유지). 상호를 바꾸면 새 번호.
- **통신 실패**(회사 PC 차단·오프라인): 실패 시 안 B 한 줄 복사로 대신 안내, 기록 안 된 건 표시.
- **웹 앱 주소 유출**: 비밀키 없으면 거절. 유출 의심 시 재배포로 주소 교체.
- **Apps Script 웹 앱은 "모든 사용자" 접근으로 배포해야** 브라우저에서 보낼 수 있다 → 비밀키가 사실상 잠금장치.
- 유형별 입력 칸이 바뀌면 매핑 함수도 같이 고쳐야 함.

## 7. 검증

- Playwright 로 6개 유형 각각 「시트에 기록」 → 가짜 엔드포인트가 받은 1줄이 열 구성과 일치하는지, 마스킹됐는지.
- 설정 없을 때 네트워크 요청 0, 한 줄 복사가 탭 구분 20열인지.
- 실제 시트 연결은 지팀 기기에서 1건 테스트 기록 → 통계 탭 반영 확인.
- `grep` 로 저장소에 script.google.com 주소·키가 없는지 확인.

## 8. 단계

1. (이번) 안 A+B 구현, Apps Script, 설치 안내.
2. (나중) **지난 카톡 기록 불러오기**: 카톡 업무방 '대화 내보내기'(.txt)를 도구에 넣으면 `[A/S]`·`[해지]` 같은 메모 줄을 찾아 시트 줄로 바꿔 준다 (기기 안에서만 처리). 도구로 만든 메모는 형식이 정해져 있어 정확히 읽히고, 손으로 쓴 옛 대화는 유형·상호 정도만 뽑아 확인 후 넣는다.
3. (나중) 직원 담당자 구분, 월간 요약 자동 메일.

## 9. 구현 중 추가 반영 (11/23 지팀 요청)
- 단순 메뉴변경·원격 처리처럼 **방문이 필요 없는 A/S 건은 주소 필수 아님**. A/S 처리에 「메뉴변경 (원격)」 추가, 「원격 처리 완료」·「메뉴변경 (원격)」이면 주소 별표·필수 빠짐에서 제외. 교체·해지(회수)·방문 점검은 그대로 필수.
